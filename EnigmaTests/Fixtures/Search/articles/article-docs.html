Configuring the Lantern cache

Lantern keeps a local cache of compiled templates so that repeated builds can skip work that has not changed. This page explains how to install the cache helper, which options control its size and lifetime, and how to clear it safely when something goes wrong during a build.

Installation

The cache helper ships as a separate command. Install it once per machine with the package manager that came with Lantern, then check that the command is on your path before running your first cached build.

lantern install cache-helper --global
lantern cache status

The status command prints the cache folder, its current size and the number of entries it holds. A fresh install reports an empty cache with no entries.

Options

Every option can be set in the project file or passed on the command line, and the command line always wins when both are present.

OptionDefaultMeaning
maxSize2 GBLargest size before old entries are removed
ttlDays30Days an unused entry is kept

Older entries are removed first when the cache grows past its limit. Entries that are still in use by a running build are never removed, even when the cache is over its limit for a short time.

Clearing the cache

  • Stop any running builds before clearing the cache.
  • Run the clear command shown below from any folder.
  • Start the next build normally; it repopulates the cache as it goes.
lantern cache clear --all

Clearing is always safe, because the cache only ever holds copies of work that Lantern can repeat. The next build is slower while the cache fills again, and later builds return to their usual speed once the common templates are cached.
